# 02. Контент сайту (CMS)

← [Логічна](./README.md) · [Головна](../README.md)

## Призначення

Публічний сайт eng-di.com — це **збирається з даних API**, а не hardcoded HTML. Адміністратор редагує контент в admin panel, зміни одразу відображаються на лендингу.

## Сторінки (Pages)

- Кожна сторінка має **slug** (напр. `home`) і **title**
- SEO: meta title, description, keywords (PageSeo)
- Сторінка складається з **секцій** — посилань на reusable **блоки**

Головна (`/`) завантажує page з slug `home` через SSR.

## Блоки (Blocks)

Reusable компоненти контенту. Типи (приклади):

| Тип | Що на лендингу |
|-----|----------------|
| Hero | Головний банер, CTA |
| About | Секція «Про нас» |
| Formats | Формати навчання |
| Levels | Рівні англійської |
| Tariffs | Тарифи (підтягує Tariff з БД) |
| Rules | Правила школи |
| Reviews | Відгуки |
| Form | Форма заявки |

Admin → **Сайт → Блоки** — редагування полів блоку (meta key-value + typed fields у UI).

Admin → **Сайт → Сторінки** — вибір блоків і порядок секцій на сторінці.

## Окремі сутності контенту

| Розділ admin | Що на сайті |
|--------------|-------------|
| **Тарифи** | Картки цін на головній |
| **FAQ** | Питання-відповіді |
| **Формати** | Як проходить навчання |
| **Правила** | Правила школи |
| **Відгуки** | Слайдер відгуків |
| **Цифри (About stats)** | Статистика «10+ років…» |
| **Медіа (іконки/зображення/відео)** | SVG і файли для блоків |

## Заявки (Leads)

1. Гість заповнює форму на сайті (блок Form або CTA)
2. Заявка потрапляє в admin → **Заявки**
3. Статуси: NEW → IN_PROGRESS → DONE
4. Категорії заявок (LeadCategory) — для сортування (напр. «Пробний урок», «Корпоратив»)

Admin може переглянути телефон, email, повідомлення, змінити статус.

## Відгуки

Два джерела:

| Kind | Опис |
|------|------|
| **manual** | Адмін створив вручну (цитата, автор, результат) |
| **user** | Учень залишив у кабінеті |

Target: **school** (загальний) або **teacher** (про конкретного вчителя).

На лендингу показуються **verified** відгуки (admin підтверджує user-generated).

## Налаштування (Settings)

**Налаштування** в admin:

- Назва школи, логотип, кольори
- Контакти (телефон, email, соцмережі)
- SMTP для листів
- Ліміти презентацій (розмір файлу, кількість)

## Потік оновлення контенту

```
Admin редагує блок/тариф/FAQ
    → POST /api/admin/...
    → MySQL
    → UserPanel SSR / client fetch /api/content/...
    → Гість бачить новий контент
```

Кеш: Next.js ISR/revalidate залежить від deploy; після зміни даних може знадобитись rebuild або revalidate (залежить від налаштувань page).

## Що не стосується CMS

- **Матеріали (curriculum)** — для вчителів/учнів у кабінеті, не лендинг
- **Заняття** — кабінет
- **Тести** — окремий модуль
