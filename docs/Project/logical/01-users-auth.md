# 01. Користувачі та доступ

← [Логічна](./README.md) · [Головна](../README.md)

## Хто користується системою

| Роль | Де працює | Що робить |
|------|-----------|-----------|
| **Super admin** | admin.eng-di.com | Повний доступ до всього |
| **Адміністратор** | admin.eng-di.com | Обмежений RBAC (ролі доступу) |
| **Вчитель** | www.eng-di.com → кабінет | Уроки з учнями, матеріали, розклад |
| **Учень** | www.eng-di.com → кабінет | Заняття, тариф, матеріали, тести |
| **Гість** | www.eng-di.com | Лендинг, заявка, без кабінету |

## Створення користувача (admin)

1. Адмін відкриває **Користувачі → Усі** або фільтр Учні/Вчителі.
2. Створює запис: email, ім'я, роль (student/teacher/admin).
3. Система генерує **тимчасовий пароль** (`pendingPassword`) — показується адміну один раз.
4. При **першому вході** учень/вчитель змінює пароль неявно через активацію (`activatedAt`).

Для учня можна одразу призначити **вчителя** (`teacherId`) — тоді вчитель бачить його в «Класах».

Для адміна — призначити **роль доступу** (AdminRole) з набором permissions.

## Вхід у систему

### Кабінет (user panel)

- URL: `/login` на www.eng-di.com
- Email + пароль
- Після входу redirect на `/cabinet/student` або `/cabinet/teacher` за роллю
- Заблокований акаунт — повідомлення «Акаунт заблоковано»

### Адмінка

- URL: admin.eng-di.com/login
- Ті самі credentials, але потрібен adminRole або superAdmin
- Звичайний учень/вчитель **не може** увійти в admin panel

## RBAC (ролі доступу)

Адміністратор без superAdmin має **роль** з permissions:

- `users.read` — бачить список користувачів
- `curriculum.write` — редагує матеріали та видає доступи
- `tests.write` — створює тести
- тощо

Sidebar показує лише ті розділи, на які є permission. Якщо потрібен доступ до тестів, але немає `tests.read` — пункт «Тести» прихований (або видимий при `curriculum.read` для read-only списку).

**Super admin** бачить усе без перевірки permissions.

## Блокування

Адмін може перевести користувача в status **blocked**:

- Не може увійти
- Існуючі сесії стають недійсними при наступному refresh

## Забутий пароль

1. Користувач → «Забули пароль?»
2. Вводить email → лист з посиланням
3. `/reset-password?token=...` — новий пароль
4. Токен одноразовий, з терміном дії

## Зв'язок вчитель ↔ учні

- У **профілі учня** в адмінці вказується `teacherId`
- Вчитель у кабінеті бачить розділ **Класи** — список своїх учнів
- Заняття, розклад, відгуки про вчителя — через цей зв'язок

## Аналітика активності

Admin → **Аналітика → Користувачі** (або Activity):

- Успішні/невдалі логіни
- Refresh сесій
- Перегляди сторінок (PAGE_VIEW)
- IP, user agent, час

Корисно для розслідування проблем з доступом.

## Типові сценарії

### Новий учень

1. Admin створює user (student) + тимчасовий пароль
2. Призначає вчителя
3. Admin або процес оплати активує **тариф** (UserTariff) → генеруються заняття
4. Учень логіниться, бачить уроки в кабінеті

### Новий вчитель

1. Admin створює user (teacher)
2. Admin видає доступ до матеріалів (**Матеріали → Доступи**)
3. Вчитель логіниться → **Бібліотека** з доступними рівнями/курсами/уроками

### Новий адміністратор контенту

1. Створити user з adminRole (напр. «Контент-менеджер»)
2. Роль має pages/blocks/reviews permissions без users.write
