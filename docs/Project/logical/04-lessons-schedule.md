# 04. Заняття та розклад

← [Логічна](./README.md) · [Головна](../README.md)

## Що таке «заняття» (Lesson)

**Lesson** — це один урок з тарифного пакету учня, не плутати з ContentLesson (матеріал).

Коли учню активують тариф, система створює N записів Lesson (number 1…N) зі статусом **unscheduled**.

## Життєвий цикл заняття

```
unscheduled → proposed → confirmed → done
                  ↓           ↓
              cancelled    missed / frozen / admin_skip
```

| Статус | Значення |
|--------|----------|
| **unscheduled** | Урок ще не має часу |
| **proposed** | Хтось запропонував дату/годину, чекає підтвердження |
| **confirmed** | Час погоджено |
| **done** | Урок проведено |
| **missed** | Пропущено |
| **frozen** | «Заморожено» (ліміт з тарифу) |
| **admin_skip** | Адмін пропустив урок |
| **cancelled** | Скасовано |

## Хто пропонує час

- **Вчитель** або **учень** може запропонувати слот (поле `proposedBy`)
- Друга сторона **accept** — статус → confirmed
- Слоти прив'язані до **календаря доступності** (ScheduleRule)

## Розклад (Schedule)

Кожен user (вчитель/учень) має правила:

| Kind | Опис |
|------|------|
| **work** | Коли доступний для уроків |
| **busy** | Зайнятий час |

Scope: щотижневий weekday, конкретна date, або daily.

Кабінет → **Розклад** — календар з:

- Підтвердженими уроками
- Пропозиціями
- Вільними слотами (work minus busy minus taken)

Контекстне меню на слоті — propose / accept / freeze тощо.

## Дошка уроків

### Учень

**Заняття** — список уроків пакету:

- Номер уроку
- Статус, дата
- Перехід на деталі → матеріал, презентація, тести

### Вчитель

**Заняття** → список учнів → уроки конкретного учня.

На деталях заняття — інформація про учня, матеріал, linked tests.

## Freeze (заморозка)

Тариф може мати `frozenLessonsPerMonth` — скільки уроків на місяць можна заморозити.

Учень/вчитель ініціює freeze → status **frozen**, урок не списується як проведений, можна перенести.

## Зв'язок з тарифом

Кожен Lesson належить:

- **UserTariff** — активний пакет
- **UserTariffPayment** — якій частині оплати відповідає (installments)

Уроки генеруються при оплаті/активації частини пакету.

## Нагадування email

Cron сканує confirmed уроки з `startsAt` у найближчі години:

- Створює **MailingTask** (unique per lesson+user)
- Відправляє лист учню/вчителю
- `reminderSentAt` на Lesson

→ [08-mailings.md](./08-mailings.md)

## Матеріал на занятті

Після **assign content**:

- Учень бачить ContentLesson або TeacherLesson
- Презентація PDF/PPTX
- Linked tests для перевірки

## Типовий сценарій

1. Учню активували тариф на 8 уроків → 8× unscheduled
2. Вчитель у розкладі пропонує понеділок 18:00
3. Учень accept → confirmed
4. За годину до уроку — email-нагадування
5. Після уроку вчитель/admin → done
6. Наступний unscheduled урок можна планувати
