# 03. Матеріали (Curriculum)

← [Логічна](./README.md) · [Головна](../README.md)

## Ієрархія

Навчальний контент організований деревом:

```
Рівень (Level)     — напр. A1, B2
  └── Курс (Course)
        └── Юніт (Unit)
              └── Урок (Lesson)  — текст, JSON content, презентація
```

Admin → **Матеріали** → окремі списки: Рівні, Курси, Юніти, Уроки.

Кожен рівень має **code** (A1) і **title**. Сортування через `sortOrder`.

## Хто бачить матеріали

| Роль | Доступ |
|------|--------|
| **Admin** | Повний CRUD усіх сутностей |
| **Вчитель** | Лише те, на що видано **grant** |
| **Учень** | Матеріал заняття, якщо вчитель призначив на lesson |

Матеріали **не публічні** на лендингу — тільки кабінет.

## Доступ вчителя (Grant)

Admin → **Матеріали → Доступи**:

1. Обирає вчителя
2. Обирає сутність (рівень / курс / юніт / урок)
3. Режим:
   - **readonly** — перегляд оригіналу
   - **fork** — може створити власну копію уроку для редагування

Grant на **рівень** дає доступ до всього дерева всередині (каскадно при перегляді бібліотеки).

Grant можна **revoke** — доступ зникає.

Також grant можна видати з картки користувача (**UserMaterialsPanel**).

## Бібліотека вчителя

Кабінет вчителя → **Бібліотека**:

- Дерево доступних рівнів/курсів/юнітів/уроків
- Детальна сторінка матеріалу: опис, контент, презентація
- **Linked tests** — тести, прив'язані до цього матеріалу або батьків у ланцюжку

## Fork (власні уроки)

Якщо grant mode = **fork**:

- Вчитель може **форкнути** урок → `TeacherLesson`
- Редагує title, description, content
- Може завантажити **свою презентацію**
- Вчительські юніти (`TeacherUnit`) — групування власних уроків

Fork не змінює оригінальний ContentLesson в admin.

## Призначення матеріалу на заняття

Коли вчитель або система **assign content** на scheduled lesson:

- У `Lesson` зберігається `contentLessonId` або `teacherLessonId`
- Учень на сторінці заняття бачить матеріал + презентацію + linked tests

*(UI assign на занятті може бути в розробці — API `assignContent` існує.)*

## Ланцюжок доступу (Content chain)

Для тестів і auto-unlock система будує **chain**:

```
lesson → unit → course → level
```

Якщо тест прив'язаний до **unit**, він видимий при перегляді уроків цього unit і при grant на unit/вище.

## Тести матеріалів

Admin → **Матеріали → Тести** — тести kind=**material** з прив'язкою entityType + entityId.

Деталі → [05-tests.md](./05-tests.md)

## Типовий сценарій

1. Admin створює curriculum: Level A1 → Course «Basics» → Unit 1 → Lesson «Greetings»
2. Admin завантажує PDF презентацію до уроку
3. Admin видає вчителю grant на Course «Basics» (readonly)
4. Вчитель відкриває бібліотеку, готується до уроку
5. На занятті учень бачить той самий матеріал (після assign)
